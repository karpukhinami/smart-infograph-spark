Google Таблица — колонки для архива генераций инфографики
============================================================

Файл для людей и для Cursor: описывает шапку таблицы, кодировку значений
и то, как приложение пишет/обновляет строки.

Порядок колонок (строго слева направо, 24 колонки):

  session_id | created_at | version | drive_link | gen_trigger | subject | class |
  topic | added content | style | profile | rating | feedback_sent | color |
  composition | artefacts | text | illustration | comment | analysis_model |
  brief_model | image_model | folder_link | image_id


Общие правила
-------------

- Одна строка = одна сгенерированная картинка (одна версия в сессии).
- Строка создаётся сразу после успешной генерации и загрузки JPEG на Drive.
- Поля rating … comment обновляются один раз, когда пользователь закрывает
  модалку мини-опросника (кнопка «Отправить» или «Пропустить» / крестик).
- Пустая ячейка = значение ещё не записано или не применимо.
- Прочерк «-» = строка опросника была показана, но ось не отмечена.


Колонки по порядку
------------------

1. session_id
   UUID сессии пользователя. Одна сессия — от первой генерации до «Начать заново».
   На Drive для сессии создаётся одна папка; все версии картинок лежат в ней.

2. created_at
   Дата и время генерации в ISO 8601 (UTC), например: 2025-06-24T14:32:01.234Z

3. version
   Номер версии картинки внутри сессии: 1, 2, 3 … (поле versionNumber в приложении).

4. drive_link
   Прямая ссылка на файл этой версии на Google Drive:
   https://drive.google.com/file/d/{fileId}/view

5. gen_trigger
   Что вызвало генерацию:
   - initial            — первая генерация («Сгенерировать»)
   - regen_image        — «Перегенерировать» картинку
   - regen_after_edit   — «Сохранить и перегенерировать» после правки контента

6. subject
   Предмет из формы / анализа (например: «Биология»).

7. class
   Класс из формы / анализа (например: «5» или «5 класс»).

8. topic
   Тема урока.

9. added content
   Был ли исходный материал помимо темы:
   - 1 = загружены файлы и/или введён текст в поле материалов
   - 0 = только тема + предмет + класс (режим «только тема»)

10. style
    Название стиля инфографики (name из настроек стилей).

11. profile
    Название дизайн-профиля (profileName), например «фиолетовая».

12. rating
    Оценка 👍/👎 после закрытия модалки:
    - 1 = нравится (like)
    - 0 = не нравится (dislike)
    До закрытия модалки — пусто.

13. feedback_sent
    Был ли отправлен развёрнутый ответ:
    - 1 = пользователь нажал «Отправить» в модалке
    - 0 = «Пропустить» или закрытие крестиком
    До закрытия модалки — пусто.

14. color
    Ось «Цвета» в мини-опроснике:
    - 1 = отмечено «хорошо» (левая сторона переключателя)
    - 0 = отмечено «плохо» (правая сторона)
    - - = ось не тронута (или опрос пропущен)

15. composition
    Ось «Композиция» — та же кодировка 1 / 0 / -

16. artefacts
    Ось «Лишние элементы» — та же кодировка 1 / 0 / -

17. text
    Ось «Текст» — та же кодировка 1 / 0 / -

18. illustration
    Ось «Иллюстрации» — особые правила:
    - пусто = при генерации не было включено ни одного переключателя иллюстраций
      (образовательные и сюжетные оба выкл.)
    - -     = переключатели были, строка в опроснике показана, но ось не отмечена
    - 1 / 0 = левая / правая сторона, как у остальных осей

19. comment
    Свободный текст из модалки. Пусто, если опрос пропущен или комментарий не введён.

20. analysis_model
    ID модели для анализа контента (models.analysis), например google/gemini-2.5-flash.

21. brief_model
    ID модели для дизайн-брифа (models.brief).

22. image_model
    ID модели для генерации картинки (models.image).

23. folder_link
    Ссылка на папку сессии на Drive:
    https://drive.google.com/drive/folders/{folderId}

24. image_id
    UUID картинки из приложения (id версии в UI). Записывается при генерации.
    Позволяет сопоставить строку таблицы с конкретной версией, если sheetRow
    на клиенте потерян.


Как приложение обновляет строку при оценке
------------------------------------------

При генерации сервер дописывает новую строку и возвращает номер строки (sheetRow).
Клиент сохраняет sheetRow в sessionStorage вместе с id картинки.

При закрытии модалки клиент вызывает PATCH /api/archive-feedback с:
  - sheetRow (номер строки в таблице)
  - rating, feedback_sent, оси, comment, showIllustrationsRow

Сервер перезаписывает колонки L–S (rating … comment) в этой строке.
Колонка image_id (X) при feedback не меняется — она заполнена при создании строки.


Папки на Google Drive
-----------------------

Структура:
  {GOOGLE_DRIVE_FOLDER_ID}/          ← корневая папка (расшарена на service account)
    2025-06-24_a1b2c3d4/             ← одна папка на session_id
      v1_1719234567890.jpg
      v2_1719234890123.jpg

Имя папки: {YYYY-MM-DD}_{первые 8 символов session_id}
Имя файла: v{version}_{timestamp}.jpg

Картинки сохраняются как JPEG:
  - длинная сторона не больше 1920 px (текст на инфографике остаётся читаемым);
  - качество ~87 % (mozjpeg);
  - типичный размер ~200–800 КБ вместо нескольких МБ PNG.


Переменные окружения (сервер)
-----------------------------

GOOGLE_DRIVE_FOLDER_ID   — ID корневой папки на Drive
GOOGLE_SHEETS_ID         — ID Google Таблицы
GOOGLE_SHEET_NAME        — (необязательно) имя листа, по умолчанию «Sheet1»

Учётные данные service account — один из вариантов:
  GOOGLE_SERVICE_ACCOUNT_JSON  — весь JSON ключ одной строкой
  или пара:
  GOOGLE_CLIENT_EMAIL
  GOOGLE_PRIVATE_KEY           — с символами \n вместо переносов строк

Корневая папка Drive и таблица должны быть расшарены на email service account
с правом «Редактор».


Переключатели иллюстраций (контекст для illustration)
-------------------------------------------------------

При генерации в строку НЕ пишется illustration — только при feedback.
Строка в опроснике показывается, если при генерации был включён хотя бы один из:
  - образовательные иллюстрации (educationalIllustrations)
  - сюжетные иллюстрации (narrativeIllustrations)

Снимок этих переключателей сохраняется в generationSnapshot на момент генерации.
