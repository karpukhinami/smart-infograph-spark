==================================================
PROMPT FOR IMAGE GENERATION
==================================================

Сформируй PromptForImageGeneration — готовый production prompt для генерации финального изображения инфографики с ясной визуальной ДНК, конкретными композиционными решениями и подробным размещением содержания, состоящий из трёх слоёв.

PromptForImageGeneration должен быть конкретным, визуальным и применённым к данной инфографике. Он не должен быть отчётом, пересказом правил или технической таблицей. Он должен описывать финальный постер так, чтобы модель изображения могла сразу его нарисовать.

Пиши PromptForImageGeneration на английском языке. Весь видимый учебный текст из ContentSummary — заголовки, основной текст, формулы, примеры, подписи и текст внутри карточек — оставляй на языке ContentSummary и переноси дословно.

При создании дизайн-брифа используй переданные правила стиля и дизайн-профиль как источник конкретных визуальных решений. Не ограничивайся общими словами вроде “accent color”, “pastel fill”, “structural color”, “geometric font”. В самом PromptForImageGeneration явно указывай конкретные hex-коды цветов и конкретные шрифтовые решения, которые выбраны из переданного дизайн-профиля.

Цвета:
- все цвета в PromptForImageGeneration должны быть выбраны только из переданного дизайн-профиля;
- если цвет важен для макета, указывай и его роль, и конкретный hex-код;
- используй hex-коды везде, где указываешь цвета внутри PromptForImageGeneration;
- не придумывай цвета вне дизайн-профиля;
- hex-коды могут присутствовать только как инструкции внутри PromptForImageGeneration; они не должны появляться как видимый текст на финальном изображении.

Шрифты:
- шрифтовой характер и конкретные шрифтовые указания выбирай только из переданного дизайн-профиля и typography settings;
- на LAYER 1 явно зафиксируй выбранный шрифтовой характер и, если профиль задаёт конкретное семейство или preferred font, укажи его;
- если профиль задаёт только характер шрифта, укажи, что используется выбранный typographic character без требования конкретной font family;
- не придумывай новый шрифт, если он не задан в профиле;
- не смешивай несколько шрифтовых систем без указания из профиля.

В начале PromptForImageGeneration напиши короткое вступление одной строкой. Не упоминай конкретный стиль в этой строке, потому что стиль задаётся отдельно.

Пример структуры вступления:
Vertical educational infographic poster, aspect ratio 3:4, Russian-language educational design, premium minimal style.

Если содержание явно лучше раскладывается горизонтально, допустим формат:
Horizontal educational infographic poster, aspect ratio 4:3, Russian-language educational design, premium minimal style.

Формат изображения:
- По умолчанию используй A4 portrait, aspect ratio 3:4.
- A4 landscape, aspect ratio 4:3 допустим только если содержание явно лучше работает в горизонтальной композиции.
- Другие соотношения сторон не использовать.

PromptForImageGeneration должен иметь такую структуру:

LAYER 1 — BRAND DNA

Этот слой фиксирует визуальную ДНК именно этой инфографики. Не копируй весь дизайн-профиль и правила стиля дословно. Применяй их к конкретной теме и конкретному ContentSummary.

На этом слое модель должна выбрать и явно зафиксировать базовые визуальные решения, которые потом будут применяться на следующих слоях.

В этом слое укажи:
- выбранный формат: A4 portrait, aspect ratio 3:4 или A4 landscape, aspect ratio 4:3;
- общий визуальный стиль и настроение изображения, например: smart, structured, premium, calm, friendly;
- конкретный цвет фона страницы из дизайн-профиля: роль + hex-код;
- конкретный главный accent color из дизайн-профиля для этой темы: роль + hex-код;
- конкретные pastel fills из дизайн-профиля, которые будут использоваться для обычных/detail-карточек: роль + hex-коды;
- конкретные structural colors из дизайн-профиля для заголовочных плашек, основного текста, вторичного текста и текста на тёмных/акцентных блоках: роль + hex-коды;
- выбранный шрифтовой характер из дизайн-профиля;
- конкретное шрифтовое семейство, если оно задано или предпочтительно в typography settings;
- если конкретное семейство не задано, укажи, что используется выбранный typographic character без требования конкретной font family;
- правила типографики для title, subtitle, meta, card title plates, body text, formulas, examples и special labels;
- характер геометрии карточек: скругление, промежутки, внутренние отступы;
- стиль иконок, если в ContentSummary есть icon;
- правила отображения формул, если в ContentSummary есть formula;
- специфические запреты именно для этой инфографики.

На LAYER 1 обязательно должны быть названы конкретные цвета с hex-кодами из дизайн-профиля и шрифтовые решения из typography settings. Дальше на LAYER 2 эти решения применяются как общая система макета, а на LAYER 3 уточняются для отдельных карточек, если это важно.

Не добавляй декоративные правила, которые противоречат переданному стилю.

LAYER 2 — COMPOSITION DECISIONS

Этот слой описывает общие композиционные решения для данного ContentSummary. Он должен быть коротким: не пересказывай содержание карточек подробно, а зафиксируй общую структуру будущего изображения.

В этом слое дай layout overview: 3–6 строк о структуре будущей инфографики. В overview укажи:
- общий маршрут чтения сверху вниз;
- главный смысловой или визуальный акцент;
- сколько основных рядов или зон будет в макете;
- какие группы ContentSummary становятся соседними карточками или зонами;
- где расположены visualCore, diagram, formula, example, warning/commonMistake и conclusion/consequence, если они есть;
- какой блок визуально закрывает композицию, если такой блок нужен;
- какие конкретные цвета из дизайн-профиля используются для ключевых зон: header, main/dominant card, ordinary/detail cards, warning, formula, visual card и closing card;
- какие типографические решения из LAYER 1 применяются на уровне всей композиции: title style, card title style, body text style, formula style, label/pill style.

На LAYER 2 обязательно указывай конкретные hex-коды цветов из дизайн-профиля там, где описываешь цветовые решения. Не пиши только “use accent color” или “use pastel fill”: укажи, какой именно accent color или pastel fill выбран, с hex-кодом.

LAYER 3 — CONTENT

На LAYER 3 должно быть конкретное описание расположения и содержания объектов, которые модель должна отрисовать, применяя выбранные на LAYER 1 и LAYER 2 правила.

В начале слоя вставь короткое напоминание для модели генерации изображения о том, что она должна пользоваться цветами, типографикой и правилами, установленными на предыдущих слоях.

Затем подробно опиши карточки и ряды строго сверху вниз. Внутри каждого ряда описывай карточки слева направо. Если несколько карточек должны стоять в одном ряду, явно напиши, что они расположены в одном горизонтальном ряду.

Используй понятные названия блоков:
HEADER
MAIN CARD
DOMINANT CARD
DETAIL ROW
CARD
VISUAL CARD
WARNING CARD
FORMULA CARD
EXAMPLE CARD
CONCLUSION CARD
ACCENT CARD

Названия блоков должны помогать читать prompt, но не должны попадать как видимый текст на изображение, если их нет в ContentSummary.

Для каждой карточки или группы карточек укажи только то, что нужно модели генерации изображения:
- положение и пропорцию карточки;
- визуальную роль карточки;
- роль фона или акцента из дизайн-профиля и конкретный hex-код, если цвет важен для карточки;
- конкретные цвета текста, заголовочной плашки, акцента, линии, бейджа или фона, если они важны для этой карточки;
- типографическое оформление заголовка, текста, формулы, примера или подписи, если это важно для этой карточки;
- точный видимый title, если он есть;
- точный видимый body text;
- точный formula text, если он есть;
- точный example text, если он есть;
- размещение icon, если icon есть;
- описание visual, если visual есть;
- короткий локальный запрет, если есть риск искажения формулы, схемы или подписи.

Не нужно повторять все hex-коды в каждой карточке, если карточки используют уже описанную общую систему. Но для header, main/dominant card, accent card, warning card, formula card, visual card и closing card цветовые решения нужно фиксировать явно: роль + конкретный hex-код из дизайн-профиля.

Не используй внутри PromptForImageGeneration длинные служебные поля вроде sectionId, entityType, priority, backgroundRole как повторяющиеся технические метки. Используй эти данные внутренне для принятия решений, но сам prompt должен читаться как арт-директорское описание изображения.

Правило дословного переноса текста:
- весь видимый учебный текст должен быть взят из ContentSummary дословно;
- не перефразируй, не сокращай, не расширяй и не заменяй термины;
- если content — массив, каждый пункт становится отдельной строкой или отдельным пунктом внутри карточки;
- если в тексте есть абзацы, они сохраняются как отдельные абзацы;
- формулы, примеры, подписи и обозначения сохраняются точно;
- не добавляй учебные факты, которых нет в ContentSummary;
- не удаляй ни одну entity из ContentSummary.

HEADER формируется из topic, subject, grade и summary:
- большой заголовок — только значение topic, дословно;
- meta показывает subject и grade, если они есть;
- summary может быть подзаголовком или короткой аннотацией;
- для header явно укажи конкретный фон, цвет заголовка, цвет meta/pill, цвет summary/subtitle и типографику, используя только дизайн-профиль;
- не выводи служебные слова TOPIC, SUBJECT, GRADE, ContentSummary, sectionId, entityType или другие внутренние метки.

==================================================
WIREFRAME SKETCH
==================================================

Сформируй WireframeSketch — простой текстовый коробочный wireframe финальной композиции.

WireframeSketch — это не изображение, не рендер, не мокап и не второй дизайн-бриф. Это грубая текстовая схема расположения карточек, чтобы пользователь быстро понял композицию.

WireframeSketch должен быть восстановлен строго по PromptForImageGeneration, а именно по тем рядам, зонам и карточкам, которые описаны в LAYER 2 — COMPOSITION DECISIONS и LAYER 3 — CONTENT.

Не проектируй для WireframeSketch новую композицию.
Не меняй порядок блоков.
Не объединяй и не разделяй карточки иначе, чем это описано в PromptForImageGeneration.
Не добавляй в WireframeSketch новые карточки, которых нет в PromptForImageGeneration.
Не пропускай карточки, описанные в PromptForImageGeneration.

Задача WireframeSketch — превратить уже описанный production prompt в простую схему “ящиков”, где каждый ящик соответствует конкретному блоку, карточке или группе карточек из PromptForImageGeneration.

Используй Unicode box-drawing characters:
┌ ┐ └ ┘ ─ │

WireframeSketch должен показывать:
- ряды сверху вниз строго в том порядке, в котором они описаны в PromptForImageGeneration;
- карточки внутри каждого ряда слева направо строго в том порядке, в котором они описаны в PromptForImageGeneration;
- примерные пропорции карточек: full-width карточка — широкая коробка; две half-width карточки — две коробки в одном ряду; three/third cards — три коробки в одном ряду;
- краткий смысл каждой карточки.

Каждая коробка должна содержать:
- короткий заголовок карточки или её роль;
- очень короткую подсказку о содержании карточки, примерно 3–8 слов.

Не используй только номера карточек. Пользователь должен понимать смысл карточки из wireframe.

Не включай полный учебный текст.
Не включай длинные описания.
Не включай цвета, hex-коды, стиль, служебные поля JSON, sectionId, entityType, priority или backgroundRole.
Не включай формулы, если формула не является главным содержанием карточки.
Не используй markdown-таблицы.

Пример желаемого вида WireframeSketch:

┌────────────────────────────────────────────┐
│ HEADER                                     │
│ Квадратные уравнения, алгебра 8            │
└────────────────────────────────────────────┘

┌────────────────────────────────────────────┐
│ ГЛАВНАЯ ИДЕЯ                               │
│ Уравнение второй степени                   │
└────────────────────────────────────────────┘

┌─────────────────────┐ ┌────────────────────┐
│ ОПРЕДЕЛЕНИЕ         │ │ КОЭФФИЦИЕНТЫ        │
│ ax² + bx + c = 0    │ │ что значат a, b, c  │
└─────────────────────┘ └────────────────────┘

┌─────────────────────┐ ┌────────────────────┐
│ ФОРМУЛА             │ │ ПРАВИЛО             │
│ D = b² − 4ac        │ │ число корней по D   │
└─────────────────────┘ └────────────────────┘

┌────────────────────────────────────────────┐
│ ВЫВОД                                      │
│ сначала D, потом корни                     │
└────────────────────────────────────────────┘

WireframeSketch должен соответствовать композиции, описанной в PromptForImageGeneration. Не придумывай для wireframe другую раскладку.
